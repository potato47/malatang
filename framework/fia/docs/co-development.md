# 框架源码共同开发

FIA 在首个正式应用中保留完整框架子树，应用稳定后再独立拆出。框架不读取应用业务源码；源码位置不是公共 API 的组成部分。

## 两种布局

- 共仓：在宿主根安装依赖，根 workspace 纳入框架的 CLI 包，只有宿主根锁文件。框架 root package 保留独立依赖声明，构建工具向上定位实际 workspace。
- 独立：导出框架目录，在框架根 `bun install --ignore-scripts` 生成独立锁文件，然后运行 `bun tools/task.ts check` 和 `bun tools/task.ts pack`。Swift Host、CLI、模板、框架契约都由该目录提供。

`tools/verify-standalone.ts` 导出源码到临时目录，排除父依赖、构建产物及缓存；独立安装并检查框架、验证实际归档，再安装该归档创建独立应用，执行检查、构建、启动和退出。

## 构建与监督

`tools/prepare.ts` 分别识别原生与 CLI 输入和输出，缓存存放在 `.fia/framework-build/`。输入包括源码/配置、构建工具、相关工具链及 CLI 依赖锁；输出包含文件内容与可执行权限。原生构建成功后单独缓存，即使后续 CLI 失败也不会丢失有效的原生缓存。完整来源报告仅在全部成功且输入未在构建期间变化时生成。

`tools/develop-app.ts <应用目录> [fia dev 参数]` 监督框架源码，防抖后先停止旧开发实例，再构建最新源码、运行新的 CLI。停止沿用 FIA 有序退出流程；原生编译不是 HMR。应用 CLI 的 `--watch-ignore <项目相对目录>` 排除框架子树，避免框架生成文件触发第二次后端重载。相似前缀目录仍可监听；不接受父路径或绝对路径。

框架依赖、根锁文件或维护工具改变后退出并提示重新运行；不在监听器里执行依赖安装。构建失败保持应用停止，修复或撤回源码后恢复。构建期间再次保存会重新验证输入，不能将中间产物标记为最新。

`tools/task.ts check|pack` 和 `tools/application-command.ts run|build|release` 共享构建互斥锁；打包期间持锁，确保消费期间产物不被另一条受管构建改写；Preview 完成构建即释放锁，运行期间可继续开发其他实例。不要并行运行绕过这些入口的裸 `cli:build/runtime:build`。异常终止的遗留锁必须先核实 owner 进程已停止，再清理。

共仓内 npm 发布命令拒绝实际发布，保留 dry-run、版本校验与归档校验供维护；独立 npm 发布仍沿用原仓库的 OIDC 配置，不能从共仓应用标签误触发。
