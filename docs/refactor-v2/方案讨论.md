# macOS Composable Application Runtime

## 最终架构设计方案 v1

## 1. 项目定位

本项目旨在构建一个 **macOS-first、可组合的 Application Runtime / GUI Framework**。

框架不是简单的 WebView Wrapper，也不是单纯的 Electron/Tauri 替代，而是以：

```text
Swift Native Host
```

作为应用核心 Runtime，并允许应用按需组合：

```text
Native UI
Web UI
Bun Backend
```

最终应用可以是：

```text
纯 Swift 原生应用
Swift + Bun
Web UI + Swift
Web UI + Bun + Swift
Native UI + Web UI
Native UI + Web UI + Bun
```

其中唯一始终存在的组件是：

```text
Swift Native Host
```

---

# 2. 核心组件

整个框架划分为四个主要 Runtime / Capability。

```text
Swift Host        必须
Native UI         可选
Web Runtime       可选
Bun Runtime       可选
```

关系：

```text
                       Swift Host
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
      Native UI        Web Runtime      Bun Runtime
   AppKit / SwiftUI      WKWebView       Application
                                         Backend
```

Swift Host 负责整个 Application Runtime 和生命周期。

---

# 3. Swift Host

Swift Host 是整个应用的核心。

它不是普通意义上的 Web Backend，而是：

> macOS Application Runtime。

主要职责包括：

```text
NSApplication
Application Lifecycle
Window Management
AppKit
SwiftUI integration
WebKit integration
Native RPC
Native APIs
Custom Swift APIs
Bun Process Management
Resource Store
Permissions
Security
Update Manager
Menu
Dock
Status Item
Dialog
Clipboard
Keychain
Notifications
Screen Capture
Filesystem integration
Code signing/runtime integration
```

因此：

```text
Swift Host ≠ Bun Backend
```

而：

```text
Swift Host = Native Runtime
```

---

# 4. UI 不强制使用 Web

WKWebView 必须被定义为：

```text
可选 Web UI Runtime
```

而不是整个框架的必需组件。

应用完全可以没有 WebView。

例如：

```text
Swift Host
   │
   ├── AppKit
   └── SwiftUI
```

形成纯原生应用。

也可以：

```text
Swift Host
   │
   ├── SwiftUI
   └── Bun Backend
```

形成原生 GUI + Bun 业务服务。

---

# 5. Window 抽象

框架核心不能假设：

```text
Window == WKWebView
```

应该定义统一 Window abstraction：

```swift
protocol AppWindow {
    var id: WindowID { get }

    func show()
    func hide()
    func close()
}
```

不同实现：

```text
WebWindow
AppKitWindow
SwiftUIWindow
```

内部：

```text
WindowManager
   │
   ├── WebWindow
   │      └── WKWebView
   │
   ├── AppKitWindow
   │      └── NSViewController
   │
   └── SwiftUIWindow
          └── NSHostingController
```

```text
├── Settings
```

# 8. Bun 的定位

Bun 是一等支持的：

```text
Application Backend Runtime
```

负责：

```text
HTTP API
WebSocket
Business Logic
Database
Networking
Background Jobs
npm ecosystem
AI SDK
File Processing
Web services
```

例如：

```ts
Bun.serve({
  routes: {
    "/api/users": {
      GET() {
        return Response.json([]);
      },
    },
  },
});
```

框架不要求 Bun 使用特定 Router、ORM 或业务框架。


# 12. Native API Protocol

Native API 不应该绑定：

```text
WKScriptMessageHandler
```

而应该：

```text
Native API
    ↓
Native RPC Protocol
    ↓
Transport
```

Transport 可包括：

```text
HTTP
WebSocket
WebKit IPC
Unix Domain Socket
```

因此：

> Native RPC 是稳定 ABI，Transport 是实现细节。

---

# 13. Native RPC

请求：

```json
{
  "id": "123",
  "method": "dialog.open",
  "params": {
    "multiple": true
  }
}
```

响应：

```json
{
  "id": "123",
  "result": {
    "files": ["/Users/example/file.txt"]
  }
}
```

错误：

```json
{
  "id": "123",
  "error": {
    "code": "permission_denied",
    "message": "Permission denied"
  }
}
```

Native RPC 至少支持：

```text
Request / Response
Async
Errors
Events
Cancellation
Capabilities
Resources
Timeouts
Exclusive Operations
```

# 14. Native RPC Dispatcher

所有 transport 最终进入：

```text
NativeRPCDispatcher
```

结构：

```text
HTTP Transport ───────┐
WebSocket Transport ──┤
WebKit Transport ─────┼──→ NativeRPCDispatcher
Unix Socket ──────────┘
                              │
                              ├── dialog.*
                              ├── clipboard.*
                              ├── keychain.*
                              ├── window.*
                              ├── screen.*
                              └── app.*
```

Native API 实现只写一次。

# 24. Native Binary Resource

Native RPC 只用于控制面。

大型数据不能长期使用 Base64 JSON。

定义：

```text
NativeResource
```

支持：

```ts
interface NativeResource {
  id: string;
  mimeType: string;
  size: number;

  blob(): Promise<Blob>;
  arrayBuffer(): Promise<ArrayBuffer>;
  stream(): Promise<ReadableStream<Uint8Array>>;
  dispose(): Promise<void>;
}
```

# 37. Whole-App Atomic Update

禁止：

```text
Frontend 单独更新
Bun 单独更新
Swift 单独更新
```

否则容易出现：

```text
Frontend API v5
Bun API v4
Native RPC v3
Swift Host v2
```

正确模型：

```text
MyApp 1.4
    ↓
MyApp 1.5
```

整个 `.app` 是唯一 release/update unit。

# 43. Bun Graceful Shutdown

更新前必须停止 Bun。

Backend SDK：

```ts
lifecycle.onBeforeShutdown(async () => {
  await database.close();
});
```

更新：

```text
UpdateManager
   ↓
stop accepting long operations
   ↓
notify Bun
   ↓
flush database
   ↓
close WebSocket
   ↓
Bun exit
   ↓
install update
```

不能在 Bun 仍运行：

```text
Contents/Helpers/Backend
```

的时候替换整个 Application Bundle。

# 44. 用户数据与 App Bundle 分离

应用本身：

```text
MyApp.app
```

应该视为 immutable。

用户数据：

```text
~/Library/Application Support/MyApp
~/Library/Caches/MyApp
```

独立存在。

不要把：

```text

mutable business files
```

写入 `.app`。

# 65. 最终架构原则

### 1

```text
Swift Host 是唯一必须存在的 Runtime。
```

### 2

```text
WKWebView 是可选 Web Runtime，不是框架根基。
```

### 3

```text
Native UI 和 Web UI 可以同时存在。
```

### 4

```text
Bun 是 Application Service Runtime，而不是 Web UI 专属 Backend。
```

### 5

```text
Frontend、Native UI 都可以消费 Bun 服务。
```

### 6

```text
Frontend 和 Bun 都可以调用 Swift Native API。
```

### 7

```text
Native RPC 是 ABI，WebKit IPC 只是 Transport。
```

### 8

```text
Chrome Dev Mode 是一等公民。
```

### 9

```text
Native RPC 使用 Control Plane + Binary Data Plane。
```

### 10

```text
大数据通过 NativeResource，不通过 Base64 JSON。
```

### 11

```text
Native Host 是安全边界。
```

### 12

```text
应用整体是唯一 release/update unit。
```

### 13

```text
Swift、Web Frontend、Bun 不独立在线更新。
```

### 14

```text
Updater 属于 Swift Host。
```

### 15

```text
更新前必须 Gracefully Shutdown Bun。
```

### 16

```text
用户数据与 Application Bundle 分离。
```

### 17

```text
Transport 永远不能泄漏进上层业务 API。
```

# 66. 最终定位

经过这些约束后，这个项目最准确的定义已经不再是：

> macOS WebView Framework

而更接近：

> **Composable macOS Application Runtime**

它以 Swift 提供：

```text
Native runtime
macOS integration
Application lifecycle
Security
Window system
Updater
```

以 Web 技术提供：

```text
可选高效率 UI Runtime
```

以 Bun 提供：

```text
可选高效率 Application Service Runtime
```

最终开发者可以根据一个窗口、一项功能甚至整个应用的性质，选择最适合的技术。

例如：

```text
Main Editor
    → React

Settings
    → SwiftUI

Capture Overlay
    → AppKit

Menu / Status Item
    → AppKit

Backend / Database / AI
    → Bun

Native APIs
    → Swift

Application Lifecycle
    → Swift Host

Automatic Updates
    → Swift UpdateManager
```

而框架负责把这些技术统一成一个可以：

```text
create
develop
debug
build
sign
notarize
update
```

的完整 macOS Application Runtime。

这应作为项目的 **v1 Architecture Contract**。

# 67. 产品定位与开发体验原则

本框架不应仅定位为：

> macOS WebView Framework

也不应仅定位为：

> Electron / Tauri Alternative

更准确的定位应为：

> **面向 macOS 的高效率 Application Framework：开发最直接、调试最方便、前端技术栈最友好，并从架构层面优先支持 Coding Agent 驱动开发。**

英文定位可以表达为：

> **The fastest way to build, debug, and ship macOS apps — with Swift, Web technologies, Bun, and AI agents working naturally together.**

框架的竞争目标不是单纯追求更小的包体积或更低的运行时开销，而是尽可能降低：

```text
idea
  ↓
code
  ↓
run
  ↓
debug
  ↓
build
  ↓
ship
```

这一整条链路的复杂度。

# 68. 四个核心产品价值

## Fast

开发启动路径尽可能短：

```text

dynamic ports
```

框架负责这些基础设施。

## Debuggable

不同组件分别使用最适合自己的调试工具：

```text

Swift
    → Xcode / LLDB

    → Bun debugger / logs
```

运行期间可以看到：

```text
[web] HMR App.tsx
[native] dialog.open
```

目标是让开发者快速判断问题究竟来自：

```text
Web
Bun
Native RPC
Swift
Window lifecycle
Permissions
```

而不是面对一个黑盒 Hybrid Runtime。

## Flexible

```text

```

```text

macOS frameworks
```

```text

```

```text

    → React

    → SwiftUI

Capture Overlay
    → AppKit

    → AppKit

    → Bun

    → Swift
```

Native UI 不是 Web 技术无法完成时的“逃生舱”。

## Agent-Native

框架应该从第一天起明确支持：

> Human Developer + Coding Agent

# 71. Native API 对 Agent 友好


```ts
const text = await native.clipboard.readText();
```

```text

authentication token
dynamic ports
JSON serialization
WebSocket framing
transport selection
```

这些属于框架基础设施。
